# Диаризация: состояние измерений

07.11.2026. **Нового DER/JER, speaker confusion, ошибки границ или Android RTF нет.** Надёжная независимая разметка реальных разговоров для нового прогона не установлена. Наличие тестов на синтетических смесях не заменяет DER на целевых данных.

Текущий offline-путь проверен по `RecordingDiarization.kt`: Nemotron 3 получает последовательные 10-секундные блоки в одной сессии; необязательный второй проход speakrs/VBx сопоставляет интервалы. Веса первичного и вторичного движка освобождаются последовательно. Для длинной записи число вторичных окон ограничивается 1800; это ограничение памяти, не измерение точности. Старое описание «основной pyannote + HAC» не полностью отражает версию 0.8.x.

Live использует отдельный WeSpeaker/инкрементальный путь. Live word-level timing намеренно отсутствует: неподтверждённую задержку T-one нельзя выдавать за точную метку. Оценочные границы offline также не forced alignment. MossFormer2 предназначен для двух источников; три одновременно говорящих не считаются поддержанными.

Доступны `speaker-a.wav`, `speaker-b.wav`, `diar-cross-window.wav`, `diar-insertions.wav` в Android test assets; demo WAV и их ограничения описаны в `ASR_BENCHMARKS.md`. Имена A/B обозначают записи, а не подтверждённые личности. Разметка из JSON не читалась по ограничению пользователя. Исторические журналы, упомянутые в context, не объявляются доступными без проверки соответствующего пути.

## Протокол следующего парного измерения

1. Создать независимую проверенную RTTM-разметку для 1/2/3+ людей, похожих голосов, коротких реплик, шума, разных микрофонов и overlap; сохранить происхождение и согласие участников.
2. Заранее закрепить scoring: основная метрика DER без collar, overlap включён; дополнительно DER с collar 250 мс и без overlap, отдельно показывая оба изменения. Сопоставлять системные ID с эталонными глобально по записи, а не по чанку.
3. DER = (missed speaker time + false alarm speaker time + confusion speaker time) / reference speaker time. Пустую эталонную речь оценивать как false alarm отдельно, не делить на ноль. Для JER закрепить ту же политику overlap и сопоставления.
4. Сравнить Nemotron; Nemotron+VBx; live предварительный результат; offline после live. Одинаковые аудио, SHA моделей, потоки и устройство. Публиковать неизвестные интервалы, фрагментацию одного голоса и ошибочное объединение разных голосов.
5. Ошибку начала/конца реплик считать относительно размеченных границ (median/p95/max абсолютной ошибки), не по внутренней монотонности. Контролировать стыки 10/30 с и длинные файлы.
6. Отдельно проверить стабильность ID после отмены/возобновления и сохранность ручных назначений. Замерить полное время и peak PSS/RSS на Android 4096 MiB.

Пороги и модели в этом аудите не изменены ради неподтверждённого выигрыша. Корпусная точность и запас памяти остаются открытыми условиями приёмки.

Для TSV-разметки добавлен `tools/score_transcript.py`: точный проход по границам, нулевой collar, overlap включён, знаменатель — время эталонных голосов, глобальная оптимальная перестановка ID (Hungarian). Выводит miss/false-alarm/confusion в миллисекундах и DER. Шесть тестов метрик прошли; это не результат DER приложения. JER и вариант collar 250 мс не реализованы в этом вычислителе.
