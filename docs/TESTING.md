# Проверки финальной версии LocalScribe

Дата автоматических проверок: 8 ноября 2026. Базовый выпуск: `v0.9.3-UX1`, Android-пакет `ru.localscribe`, версия `0.9.3-dev`, versionCode `23`.

## Демонстрация на телефоне

В [полном видео](https://github.com/zxcd3v/LocalScribe/releases/download/v0.9.3-UX1/LocalScribe-demo.mp4) показана работа на Samsung Galaxy S23 Ultra (SM-S918B): отключение Wi-Fi и мобильных данных, авиарежим, импорт локальной записи, обработка, просмотр и экспорт.

| Параметр | Результат демонстрации |
|---|---|
| Аудиофайл | `interview.wav` |
| Длительность | 21 секунда |
| Определено участников | 2 |
| Блоков текста | 4 |
| RTF в интерфейсе | 1,27 |
| Экспорт | `dialogue-offline.json`, 952 байта |
| Дополнительные действия | Воспроизведение, краткий итог, конспект, плавающая кнопка, запуск записи микрофона |

RTF — отношение времени обработки к длительности аудио. Значение 1,27 относится к показанному запуску; его нельзя использовать как среднюю скорость на других устройствах. Видео смонтировано из реальных записей экрана с сокращением ожидания, поэтому по длительности ролика время обработки не рассчитывается.

Тесты утилиты метрик проверяют перестановку ID участников, одновременную речь, пропущенную речь, ложную активность, смену идентификатора и оптимальное сопоставление голосов. Они проверяют вычисление метрик, а не качество распознавания аудио.

Проверки прогресса охватывают начальное состояние, продвижение, паузу в продвижении, смену этапа, завершение, сброс и некорректный входной сигнал.

Пересборка дала неподписанный APK. Его установка и запуск на Android в эту проверку не входили. В Releases сохранён исходный подписанный APK финальной версии LocalScribe.

## Как повторить

Команды выполняются из корня репозитория. Нужны Python 3.11+ и JDK 21; вывод Python ограничен 30 строками.

```bash
python -m unittest discover -s src/tools -p test_score_transcript.py -v 2>&1 | head -n 30
mkdir -p build/ux1-tests
javac -encoding UTF-8 -d build/ux1-tests \
  src/ux1/src/ru/localscribe/ux/ProgressEstimate.java \
  src/ux1/tests/ProgressEstimateTest.java
java -cp build/ux1-tests ProgressEstimateTest
```

В PowerShell вместо `head -n 30` используйте `Select-Object -First 30`. Успех команды Python проверяйте также по коду завершения процесса (`$LASTEXITCODE` в PowerShell); конвейер может скрывать ошибку.

## Протокол оценки качества

Для числовой оценки нужны исходные аудиозаписи, ручные эталоны и экспорты приложения для тех же файлов. В таблице выше приведены результаты функциональных проверок и демонстрации. Числовые WER, DER и ошибки границ реплик в этот отчёт не включены.

1. Подготовить минимум три записи с разными голосами и условиями: чистый диалог, фоновый шум, перебивания. Сохранить SHA-256, длительность и число участников каждого файла.
2. Вручную разметить текст, говорящих, начало и конец реплик. Проверить разметку вторым участником команды.
3. Установить финальную версию LocalScribe. До первого запуска отключить Wi-Fi и мобильные данные. После подготовки моделей выполнить импорт, обработку и экспорт.
4. Сохранить модель телефона, версию Android, настройки обработки, фактическое время обработки и версию APK. Отдельно записать время первоначальной подготовки моделей.
5. Для каждого файла сравнить экспорт с эталоном. Повторить замер скорости трижды; привести отдельные значения и медиану RTF, не включая подготовку моделей.
6. Привести WER и DER для каждого файла и общие значения, взвешенные по числу эталонных слов и времени эталонной речи соответственно.

Утилита принимает UTF-8 TSV с заголовком `speaker_id`, `start_ms`, `end_ms`, `text`, разделитель — табуляция. Экспортированный JSON можно перенести в этот формат, сохранив текст и интервалы без исправлений. В эталоне и результате нужен одинаковый порядок одновременно начавшихся реплик.

```bash
python src/tools/score_transcript.py reference.tsv hypothesis.tsv 2>&1 | head -n 30
```

WER рассчитывается по словам после NFKC-нормализации и приведения регистра; пунктуация игнорируется, различие `е`/`ё` сохраняется. DER рассчитывается по точным интервалам, с учётом наложений, без допуска на границах (collar = 0) и с оптимальным взаимно однозначным сопоставлением ID участников. Это внутренний протокол команды; методика жюри может отличаться.

Для временных меток отдельно сопоставить реплики и привести медиану и 95-й перцентиль абсолютной ошибки начала и конца, а также количество несопоставленных реплик. WER и DER не заменяют эту проверку.
